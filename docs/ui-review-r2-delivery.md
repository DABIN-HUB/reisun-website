## 1. 保留的边界

- REISUN 标识、深海蓝/科技蓝/冷白配色、首页设备—数据—业务分层原创 HeroGraphic、主导航与既有路由未替换。
- 服务、方案、案例本地数据、全部 Markdown/MDX 文稿、内容 schema、博客工具和原生博客路由、RSS、Sitemap、SSG 保留。
- 联系方式仍由 `src/data/brand.ts` 集中管理，电话/邮箱/微信为待配置，不生成可拨打/可发送的假联系方式。
- 联系页 `<script>`、`<form>` 和 `<reisun-contact-demo>` 与本轮基线逐字节一致。
- 无 Git 操作、提交、分支操作、部署、Docker/服务器/Cloudflare 改动、数据库或真实咨询后台接入；无测试代码/脚本/依赖的新增或运行。
- 第一阶段交付记录与截图未覆盖；本轮单独保存 baseline、working、candidate 证据。

## 2. 六项精修

### R2-01 首页手机阅读节奏

- 保留完整 Hero 与双 CTA、六服务、四演示案例、四方案、六步流程、关于引导、最新三篇文章、合作 CTA 与 Footer。
- 合并服务与方案的重复详情入口，标题链接保留清楚箭头和实际目标，不增加整卡嵌套链接。
- 手机服务摘要由原 13px 调至 14px，而不是压小正文来缩短页面。
- 工业方案采用原创业务链路图，避免与案例区重复展示同一仪表盘。
- 首页文章在手机上使用缩略封面、标题和分类/日期/阅读时间摘要行；完整摘要、标签及正文仍可在原生博客列表/详情阅读。桌面保持三列。
- 使用首页专用的紧凑流程表现，完整六步与描述保留。

同一 390×844 视口、字体与图片就绪条件下：首页高度由 **11003px → 9399px，减少约 14.6%**；1440px 由 **6588px → 6575px**。这是阅读组织调整的观测值，不是 UX 改善的唯一证明。

### R2-02 服务页

- 六项真实锚点目录：桌面位于 Header 下粘性定位，手机两列三行可直接发现，不依赖横向滚动。
- 六模块均区分业务问题/场景、能力、交付物、技术方向、范围与前置条件、关联方案和咨询入口；每节有返回目录入口。
- 增加工业设备→采集→监控→告警、业务单据→审批→执行→汇总、小程序操作→后台办理三种原创静态场景图。
- 有场景图模块使用图文加横向能力分栏，其他模块使用概览与能力清单，避免六节完全同构。
- 从原始数据读取的每项服务 21 个正文/能力/场景/交付/技术字段均在构建 HTML 中找到，无缺失；六条首页摘要亦全部保留。

增加场景图和完整分层后，服务页 390px 高度由 12908px 变为 14651px，1440px 由 7969px 变为 8643px。本轮没有以缩短服务页为目标删内容；重点是分层、可定位和可理解的图示。

### R2-03 内页顶部差异化

共享 `PageIntro` 使用显式、类型化 variant，保留标题/描述和统一容器与字体：

| 栏目     | 表现                                     |
| -------- | ---------------------------------------- |
| 开发服务 | 工程交付纸页、需求边界/模块实现/文档交接 |
| 解决方案 | 深海蓝业务连接链路                       |
| 项目案例 | 浅色作品叠窗，明确概念演示               |
| 技术文章 | 编辑式阅读索引、分类与知识主题           |

| 联系合作 | 沟通准备纸页与下一步信息                 |

手机使用紧凑语义提示，不把桌面大插图整体缩成小字。

### R2-04 四类系统概念画面

- 工业：设备状态、协议采集链路、摄氏度双曲线与时间刻度；详情图补充离线模拟与告警待确认示例。
- ERP/OA：单据数量概览、分类统计、待办状态和采购→审批入库→数据汇总关系，手机不再隐藏全部待办。
- 合同：发起/审核/确认/归档阶段，明确完成、当前和等待状态。
- 小程序：放大手机比例，用移动提交→后台受理→进度反馈说明前后端衔接；窄嵌套容器改排右侧说明，而不继续压小核心文字。
- 使用容器查询适配实际组件宽度，而非仅根据整页 viewport 缩放。手机优先移除装饰性后台侧栏，保留可理解的信息。
- 所有画面继续标明原创概念/全部模拟/非真实系统，不新增可误认为实际操作的空按钮。

### R2-05 文章体验

- 分类导航强于次级标签；技术标签使用原生可折叠入口，当前标签页默认展开。
- 列表保留封面、完整摘要和标签，改善标题、分类、发布日期、阅读时间关系。
- 正文保持桌面 760px 阅读宽度、手机 16px 正文与舒适行高，代码保持已配置的高对比 Shiki 配色与局部滚动边界。
- 基于同一内容集合条目原生 `render(entry).headings` 生成折叠目录，复用编译器 slug，不猜测或修改正文标题 ID。
- 相邻文章补充日期，保留推荐算法、分类标签路径工具与返回文章列表入口。
- 未修改文章事实，未新增文稿，未修改原生博客路由/工具/schema。

### R2-06 联系页

- 需求准备、演示表单、正式联系方式占位分层，桌面两栏、手机顺序清楚。
- 二维码占位采用明确“不可扫描”的紧凑说明，不生成伪二维码。
- 演示提交保留原提示：**当前为演示模式，暂未开通在线提交，请通过正式联系方式联系。**
- 完整表单、脚本和 custom element 与基线一致，未更改四字段属性、输入保持、禁用启用或生命周期逻辑。
